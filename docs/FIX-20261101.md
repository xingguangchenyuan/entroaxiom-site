### 为什么 P0-2、P1-9 不改

- **P0-2**：文章发布的 `doPublish()` 与 `PublishRequest` 本来就是全字段透传，实测断点/冒烟都能看到 `assetDecisions` 到达 mock。
  真丢了的是**书影音**（P0-3），任务书把两者写在一起，容易误判。
- **P1-9**：前台请求 `/api/public/guestbook?offset&limit`，后台请求 `/api/admin/guestbook?page&page_size`，
  是两个不同端点、两套消费方，`pagedQuery()` 已经把 `pageSize` 映射成 `page_size`。
  强行"统一"反而会让其中一端不得不做无意义转换。真正缺的是**分页边界的自动化覆盖**，这一条留作后续（见第五节）。

## 三、契约清单（前后台必须一致的部分）

| # | 契约 | 谁产出 | 谁消费 |
|---|---|---|---|
| C1 | 公开文件地址唯一形态 `/uploads/public/<fileId>.<ext>`；私密文件 `publicSrc/publicUrl = null` | 后台 | 前台 `<img>`、Nginx |
| C2 | `FileItem` 双写：`publicSrc`/`publicUrl`、`visible`/`visibility`、`mime`、`status` | 后台 | 前台按 `publicUrl → publicSrc → src` 降级 |
| C3 | `ShelfItemAdmin.coverUrl`：公开地址或 `null`；管理端内部仍存 `cover = asset:<id>` | 后台 | 前台书架封面 |
| C4 | 公开内容的 `body` 中**不得出现** `asset:`；发布快照另存 `publicBody` | 后台 | 前台正文渲染 |
| C5 | `checkId` 绑定 用户/对象/action/targetVisibility/revision/私有资源集合/5 分钟 TTL，服务端原子消费 | 后台 | 后台自身（编辑页、书影音页） |
| C6 | 错误码 `CHECK_EXPIRED`（过期）/ `CHECK_MISMATCH`（不符），两者都要重新预检 | 后台 | 后台前端 |
| C7 | 列表接口 404 ≠ 空列表；详情接口 404 = 内容不存在 | 后端 | 前台 `api.ts` |
| C8 | 鉴权目标形态：HttpOnly+Secure+SameSite=Strict Cookie 会话 + 写操作校验 `Origin` + 刷新轮换 | 后端 | 后台前端 |
| C9 | 子路径部署：`VITE_PUBLIC_PATH` 与 `VITE_ROUTER_HISTORY` 必须成对设置 | 构建期 | Nginx |

C5/C6 已在 Mock 层完整实现，后端照 `docs/ADMIN_API.md §4.4` 的绑定表实现即可。
C8 是**唯一没能在代码里完成的一条**：没有后端就无法真正下发 HttpOnly cookie，仓里给的是
"客户端侧硬化 + 契约"，`auth.ts` 已把 refreshToken 移出可读 cookie、`ADMIN_API.md §1.5` 写了服务端要求。
